1What is an agent?

A model can only say words. An agent is the loop that turns those words into effects on the world: it asks a model what to do, reads the reply as a call to a tool, runs the tool, feeds the result back as an Observation, and repeats until the model gives a Final Answer. The model supplies intent; the loop supplies procedure.

A model writes words; the agent's loop turns a ToolCall into a Tool result, feeds it back as an Observation, and stops on a Final Answer.

2The loop

The agent is a small loop with one job: take a task, feed it to the model, read the model's reply as an action or an answer, run any tool the model asked for, feed the result back as an Observation, and repeat — until a Final Answer, the step budget runs out, or a failure stops it.

The loop: task → memory → model → action → tool run → observation → memory → (repeat or stop).

3Context / memory

The model only sees what the loop puts in front of it. Memory is a ContextWindow: every message appended gets a token estimate, the system message is sacred (never evicted), and when the budget would overflow the oldest non-system turn is trimmed. Age-first keeps it simple and predictable — the right first lesson for "the LLM context is a cache."

System stays; oldest non-system turns get trimmed first when the token budget overflows.

4Tools, registry & prompt-craft

A model can only say words; tools are how words become effects on the world. Each tool bundles data (name, description, a JSON-schema-ish params, and a function) so documentation and implementation can never drift. The registry is a phonebook, not a dispatcher: it answers "which tools exist?" and "what is tool X?" The catalogue it renders is pasted — byte-for-byte — into the system prompt, so the model's entire world of capabilities is what it's been told exists.

Tool → registry → catalogue pasted into the system prompt → model calls only what exists.

In this repo

  • asa/tool.py — Tool + ToolCall + ToolResult, validate-before-execute, failure is data
  • asa/registry.py — render_catalogue(), sorted by name, empty = a sentence
  • asa/agent.py:77-101 — _compose_system_prompt pastes the catalogue

5Parsing / two protocols

The agent core speaks only ToolCall(name, args). Two protocol adapters feed it. The textual ReAct adapter teaches the model a grammar (Thought: / Action: / Action Input:), parses it with regexes, converts values safely (no eval), and repairs drift with gentle notes. The native adapter reads a structured functionCall from the API — args already typed, nothing to repair. Same core, two adapters.

Two adapters, one core: ReAct parses prose; native reads a typed functionCall; both become ToolCall.

In this repo

  • asa/protocol_react.py — ReAct letter reader (M4)
  • asa/protocol_native.py — functionCall shim, no eval/repair (M9)
  • asa/tool.py — mini-schema convertible to real JSON Schema for M9

6The brain zoo

To the agent, any model is just a text-in/text-out box: complete(messages) → Completion. Swapping the brain never changes agent code — that swap is the lesson. The zoo holds MockBrain (deterministic, offline), OllamaBrain (local lfm3:latest, ~7.2 tok/s on the Pi5, thinking on), and GeminiBrain (cloud, gemini-3.5-flash-lite, key in a header only, thought parts filtered).

MockBrain, OllamaBrain (lfm3), GeminiBrain — all behind the same complete() seam; the agent loop never changes.

In this repo

  • bench.py — same task across brains, procedural "ok" only

7Observability & failure modes

Every internal step is one JSONL trace event: {ts, iter, kind, payload}. Fourteen kinds — session.start … agent.answer — record brain requests/responses, protocol parses, tool lookups/invokes/results, loop turns, and termination. Each run gets a run_id so failures separate cleanly in the shared trace. Failures are data, not crashes: empty replies, protocol drift, tool errors, network blips, budget exhaustion, and rate limits are all named in the trace. The detective lab replays failing runs to bisect what went wrong.

Trace events → named failure taxonomy → detective lab replays failing runs.

In this repo

  • asa/trace.py — write/read/clear JSONL events, run_id, 14 kinds
  • asa/agent.py — records brain failures as trace events (M8.4.4)
  • lab/detective_lab.py — groups by run_id, extracts failure contexts
