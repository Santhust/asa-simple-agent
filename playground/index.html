1Architecture diagram

The core speaks only ToolCall(name, args). Two protocol adapters feed it (ReAct text vs native function calling); the loop — memory, brain, protocol, tools, trace — is identical for every brain.

Task → Brain → ToolCall → Tool runs → Observation → Final Answer. The loop is protocol-agnostic.

3Breakage lab

Failures are data, not crashes. When the model writes a broken letter (no Action:, no Action Input:), the parser returns a gentle note instead of an exception. The model reads the note, corrects its format, and retries — drift → observation → repair.

Broken letter → gentle note → retry

Model: "This is not a letter at all."
Parser: error — "Could not read this reply as ReAct. Expected lines like:
  Thought: ...
  Action: tool_name
  Action Input: key=value ...
Or use 'Final Answer: ...' to end."
Loop: feeds that note back as an Observation
Model (next turn): writes a correct Action: calculator / Action Input: ...

Failure taxonomy

empty_reply

Model returned blank text → gentle note, retry

protocol_drift

Reply doesn't match ReAct grammar → gentle note, retry

tool_error

Tool rejected args or raised → ToolResult(is_error), fed back

budget_exhausted

max_steps reached without answer → terminate, report reason

network

Ollama/Gemini unreachable → recorded, not propagated as crash

rate_limited

HTTP 429 → gentle retry with Retry-After, then guidance

4Two-protocol comparison

Same agent core, same ToolCall(name, args) box, two protocol adapters underneath. ReAct (textual letters) vs native (API function calling). Measured side-by-side on the same task: drift, repair, steps, tokens, wall time.

ReAct (M4 — textual)

  • Model writes Thought:/Action:/Action Input: in prose
  • Parser uses regexes + literal_eval (no eval)
  • Drift → gentle note → self-repair (M4.3)
  • Real drift observed (M7.3) needing self-repair

Native (M9 — function calling)

  • API returns structured functionCall {name, args}
  • Args already typed — numbers as numbers, bools as bools
  • No regex, no literal_eval, no repair
  • Zero drift, ~3.5× faster (live Gemini, M9.3)

Live side-by-side result (Gemini, task "compute 7*6")

Both reach final_answer (procedural success, not truth). Native skips the parse/repair hop entirely.

5Model zoo & glossary

To the agent, any model is just a text-in/text-out box: complete(messages) → Completion. Swapping the brain never changes agent code — that swap is the lesson.

MockBrain

deterministic, scripted · tests · offline demo · golden traces

OllamaBrain

local · lfm3:latest (1.7B, Q4_K_M) · ~7.2 tok/s on Pi5 · thinking on · stdlib urllib

GeminiBrain

cloud · gemini-3.5-flash-lite · key in header only · thought parts filtered · native function calling

Glossary

ToolCall
name + args — the only vocabulary the core speaks
ToolResult
output + is_error — failure is data, not an exception
ContextWindow
memory: append, token estimate, age-first trim, system sacred
Verdict
thought_action / final_answer / error — parser output
run_id
identity per agent run — separates evidence in the shared trace
Final Answer
third verdict — ends the loop when the model answers
max_steps
budget guard — terminates when steps are exhausted
Failure is data
errors become Observations the model can act on, never crashes
